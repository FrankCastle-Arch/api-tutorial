Fetching Data from the Dog CEO API

Send a request, parse the JSON, and turn it into a random dog image on the page.

Step 1 — Send the request

What I did: I sent a GET request to https://dog.ceo/api/breeds/image/random using Postman. What I saw: The response came back as a JSON object containing a random dog image URL and a status field confirming the request succeeded.

Dog CEO API documentation

{
		"message": "https://images.dog.ceo/breeds/mountain-bernese/n02107683_3609.jpg",
		"status": "success"
		}

Step 2 — Request three hounds

What I did: I entered https://dog.ceo/api/breed/hound/images/random/3 directly into my browser's address bar to request three random hound images at once. What I saw: The response returned a JSON object with a message field containing a list of three image URLs, instead of just one — showing how the API can return multiple results in a single request."

{
		{
		"message": [
        "https://images.dog.ceo/breeds/hound-basset/n02088238_10051.jpg",
        "https://images.dog.ceo/breeds/hound-basset/n02088238_13683.jpg",
        "https://images.dog.ceo/breeds/hound-english/n02089973_4055.jpg"
		],
		"status": "success"
		}
		}

Reflection #1: When JSON breaks

Today I learned what happens when a JSON field name is missing its quotes — the response stops being valid JSON and the browser refuses to parse it correctly. It was a good reminder that every property name inside an object needs to be wrapped in quotes, even though it's easy to forget when you're used to writing regular JavaScript objects. Seeing the broken response made the strict formatting rules of JSON click in a way that just reading about them hadn't.


	// Broken — missing quotes around the property name
		{
		message: "https://images.dog.ceo/breeds/hound/example.jpg"
		}
	// Correct
		{
		"message": "https://images.dog.ceo/breeds/hound/example.jpg"
		}
