Reflection #1: When JSON breaks

Today I learned what happens when a JSON field name is missing its quotes — the response stops being valid JSON and the browser refuses to parse it correctly. It was a good reminder that every property name inside an object needs to be wrapped in quotes, even though it's easy to forget when you're used to writing regular JavaScript objects. Seeing the broken response made the strict formatting rules of JSON click in a way that just reading about them hadn't.


	// Broken — missing quotes around the property name
		{
		message: "https://images.dog.ceo/breeds/hound/example.jpg"
		}
	// Correct
		{
		"message": "https://images.dog.ceo/breeds/hound/example.jpg"
		}

Reflection #2 Part #1: Parameters change the shape of the response

Sending the same kind of request to two different endpoints today showed how much a small addition to a URL can change what comes back. A plain request returned a single object, but adding /3 to ask for multiple hound images turned the message field into a list instead of a single string. It made the connection between what you ask for and the structure of the response a lot more concrete.


// Single request — no parameters
	{
	 "message": "https://images.dog.ceo/breeds/hound/example.jpg",
	 "status": "success"
	}

// Same kind of request, with /3 added — "message" becomes a list
	{
	"message": [
    "https://images.dog.ceo/breeds/hound/example1.jpg",
    "https://images.dog.ceo/breeds/hound/example2.jpg",
    "https://images.dog.ceo/breeds/hound/example3.jpg"
	],
	"status": "success"
	}

Reflection #2 Part #2: Not every API needs a key

The coffee menu request was a good contrast to everything else today — no key, no headers, no setup, just a plain URL that answered immediately. Comparing it against the dog API's requests made it clearer that authentication and headers are a choice each API makes, not something every request needs by default.


// Dog CEO API request — plain URL, no headers, no key
GET https://dog.ceo/api/breeds/image/random

// Coffee Cart API request — same simplicity
GET https://coffee-cart.app/list.json

// Both return a 200 with no authentication required
